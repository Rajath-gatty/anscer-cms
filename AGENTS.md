## Architecture Patterns

### Route Groups
- `(app)` — Public-facing website. All pages share a layout with SiteHeader, SiteFooter, and MotionProvider.
- `(payload)` — CMS admin panel. Auto-generated by Payload; do NOT modify `layout.tsx`.

### Component Organization
- **Page-specific components** live in the page directory or in underscore-prefixed subdirs (`_components/`, `_data/`).
- **Shared components** live in `app/(app)/components/` organized by domain (home, animation, series, robots, product-detail, marketing).
- **UI primitives** live in `components/ui/` (shadcn managed).
- **Data files** use the `*-data.ts` naming convention (e.g., `series-data.ts`, `product-detail-data.ts`, `home-data.ts`).

### Page Pattern (Product Detail)
Product pages are thin wrappers that import data and pass it to a shared template:
```tsx
import { ProductDetailPage } from "../../components/product-detail/ProductDetailPage";
import { productDetails } from "../../components/product-detail/product-detail-data";

const data = productDetails["ar-250"];
export default function Ar250Page() {
  return <ProductDetailPage data={data} />;
}
```

### Page Pattern (Series)
Series pages use the same pattern with `SeriesPage` component and `seriesPages` data.

## Styling Conventions

### TailwindCSS v4
- Config is in `globals.css` using `@theme inline` and `@theme` blocks (NOT `tailwind.config.ts`).
- PostCSS plugin: `@tailwindcss/postcss`.
- shadcn uses CSS variables with oklch color format.

### Brand Colors
| Name | Hex | CSS Variable | Tailwind Class |
|------|-----|-------------|----------------|
| Brand Blue | `#005ead` | `--brand-blue` | `text-brand-blue`, `bg-brand-blue` |
| Brand Navy | `#011f40` | `--brand-navy` | `text-brand-navy`, `bg-brand-navy` |
| Brand Charcoal | `#363636` | `--brand-charcoal` | `text-brand-charcoal` |

### Typography
- **Headings**: `font-montserrat` (Montserrat via next/font, variable `--font-montserrat`)
- **Body text**: `font-inter` (Inter via next/font, variable `--font-inter`)
- Applied via `@layer base` rules: `h1-h6` get Montserrat, `p/span` get Inter.
- `--font-sans` maps to Montserrat (default sans-serif).

### Custom Breakpoints
- `3xl`: `120rem` (1920px)
- `4xl`: `130rem` (2080px)

### Layout Utility
- `.site-container` — responsive centered container: `max-width: clamp(1340px, 90vw, 2200px)`, `padding-inline: 20px` (24px on mobile).

### Component Styling Pattern
- Inline Tailwind classes (no CSS modules).
- `cn()` helper from `lib/utils.ts` for conditional class merging.
- `class-variance-authority` for component variants (button, etc.).
- Responsive text uses `clamp()`: e.g., `text-[clamp(16px,0.8vw,30px)]`.

## Animation System

### MotionProvider
Wraps the app in `<LazyMotion features={domAnimation}>` for tree-shaking Motion.

### Reveal Component (`app/(app)/components/animation/Reveal.tsx`)
Primary entrance animation system. Viewport-triggered, fires once.

**Variants**: `fade`, `fade-up`, `fade-down`, `fade-left`, `fade-right`, `scale-up`, `scale-down`

**Convenience exports**: `FadeIn`, `FadeUp`, `FadeDown`, `FadeLeft`, `FadeRight`, `ScaleUp`, `ScaleDown`

**Usage**:
```tsx
import { FadeUp } from "../components/animation";

<FadeUp delay={0.1}>
  <h2>Content</h2>
</FadeUp>
```

### Reduced Motion
- `useReducedMotion()` hook skips all animations.
- CSS `@media (prefers-reduced-motion: reduce)` kills keyframe animations and transitions globally.

### CSS Animations
- `.reveal` — CSS-only reveal-up keyframe.
- `.section-reveal` / `.section-reveal-visible` — intersection-observer-driven CSS class toggle pattern.
- `.logo-marquee` — infinite horizontal scroll for client logos.
- `.footer-card-reflection` — decorative light sweep animation.

## Key Conventions

1. **Server Components by default** — Only add `"use client"` when needed (interactivity, hooks, browser APIs).
2. **RSC data fetching** — Use Payload's `getPayload()` directly in server components.
3. **No `tailwind.config.ts`** — TailwindCSS v4 uses CSS-first configuration in `globals.css`.
4. **shadcn style: base-vega** — When adding components, use `npx shadcn add <component>`.
5. **Static product data** — Product specs/details are in TypeScript data files, not CMS (only Articles, CaseStudies, Teams are CMS-managed).
6. **Image optimization** — Use `next/image` with quality settings [75, 95]. Remote patterns configured for CDN.
7. **Viewport-triggered animations** — Use `Reveal`/`FadeUp` etc. for entrance animations, not scroll-linked.
8. **Metadata pattern** — Each page exports a `metadata` const with title and description.
9. **Brand consistency** — Always use brand color variables/classes, not raw hex in new code.
10. **Accessibility** — Reduced motion support required for all animations. Use semantic HTML. Buttons must be focusable.
